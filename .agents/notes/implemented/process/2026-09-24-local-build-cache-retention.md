# Agent Note: 本地构建缓存与验证资料保留边界

Status: implemented

## Problem

Cargo 的开发配置默认生成完整调试信息和增量编译文件，多个构建目录会长期保留依赖产物；项目内 `target/` 曾因此膨胀。旧验证沙盒还各自保存 Edge/WebView2 资料。当前 `.tmp/` 约 1.70 GiB，其中 README 截图、Claude UI、网页和网关验证沙盒的浏览器资料占主要部分。`.gitignore` 只阻止提交，不回收磁盘。项目内的 0.3.1 安装包和验证截图需要保留。

## Decision

工作区的 Cargo 开发配置只生成行号级调试信息、依赖不生成调试信息，并关闭增量编译；测试配置继承开发配置，发布配置不变。`prune-local-artifacts.ps1` 只处理 `target-dev/debug`、`target/debug`、发布目录里明确的中间产物子目录，以及项目自有的五处验证浏览器资料。默认只报告，显式 `-Apply` 才按最近写入时间和容量预算移除过期资料；沙盒资料保留最近三天且预算为 0.5 GiB，Rust 缓存保留最近一天且每组阈值为 8 GiB。脚本保留验证脚本、截图、安装包、发布可执行文件和其他 `.tmp` 内容，删除前重新核对规范化路径并拒绝重解析点。README 记录使用方式和重新构建的代价。

## Alternatives considered

- 直接定期删除整个 `target/` 和 `.tmp/` 最容易执行，也能迅速释放空间；但会删掉 0.3.1 安装包、截图和可能仍在使用的验证环境。
- 把 `CARGO_TARGET_DIR` 移到项目外可使项目目录看起来更小；但实际磁盘占用不变，还会让清理归属不清。
- 每次发布构建后删除所有 Rust 中间产物可压低静态占用；但会显著增加下一次构建时间，且未经当前请求授权的编译无法验证发布脚本改动。

## Consequences

- 开发与测试的后续构建不再生成工作区增量缓存，调试信息仍保留定位回溯所需的行号；发布配置不受影响。关闭增量编译可能使小改动重编译变慢，变量级调试可在单次构建覆盖配置。
- 清理命令的只读预演列出约 1.68 GiB 的过期浏览器资料；显式执行后删除五处资料目录，验证截图、脚本及 0.3.1 安装包保留。浏览器资料删除后若需复现旧验证状态，必须重新运行对应验证。
- 容量预算只在显式运行清理命令时生效，不能限制构建过程中的峰值空间；本次依仓库约束未运行 Rust 编译或测试，开发配置的实际容量收益待下一次获准构建观察。
