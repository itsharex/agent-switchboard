# Agent Note: 会话记录的项目筛选与结果布局

Status: implemented

## Problem

会话记录在应用常用窗口宽度下触发 1250px 响应式断点，项目目录从侧栏变成独占高度的横排。工作目录在按钮里任意换行，未重置的按钮默认边框又把项目项画成大卡片；结果列表和详情被推到下方，页面高度被非核心导航消耗。页签右侧和搜索行同时堆放多个完整描边按钮，操作层级不清。

## Decision

项目筛选放在会话结果列表顶部，用现有选择器显示客户端、完整工作目录和该目录的会话数；选中的目录暂时不在新扫描结果中时仍保持可见。结果列表与详情直接组成双栏，项目不再占据独立主行，也不保留 1250px 横排卡片规则。搜索和刷新使用已有图标按钮，批量选择使用轻量文字动作；名称、键盘提交方式与筛选行为不变。样式只消费现有设计 token。

## Alternatives considered

- 把项目侧栏断点从 1250px 降到 900px，可保留一次看到多个项目的浏览方式；但应用最小窗口内，项目栏和结果栏会挤压含固定对话大纲的详情，正文列过窄。
- 保留横排项目卡片并修正边框与截断，代码改动最少；但项目仍占一整行、遮住更多结果，不能解决当前截图最明显的信息层级问题。

## Consequences

- 常用窗口宽度下项目不再占据独立的一行；列表和详情恢复已有的双栏尺寸，窄窗口沿用现有堆叠布局。
- 项目菜单有高度上限，可滚动；最初采用长目录换行，后续改为单行目录末段显示，见[操作层级与长内容布局](2026-09-24-session-operations-layout.md)。触发器仍截断，完整选中目录保留悬浮提示；逐条结果中的目录动作移除浏览器默认边框。
- 项目不再常驻平铺，切换项目多一次展开操作；这换取了更多会话内容的可见面积。
- 本次按仓库当前请求的验证限制只检查源代码、旧类名和笔记结构；运行时布局仍需在下一次获准构建后目视核对。
- 后续项目菜单长路径及整页操作层级的调整见[会话记录操作层级与长内容布局](2026-09-24-session-operations-layout.md)；此篇关于项目筛选位于结果列表内的决定仍然有效。
