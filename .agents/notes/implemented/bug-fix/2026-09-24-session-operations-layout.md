# Agent Note: 会话记录操作层级与长内容布局

Status: implemented

## Problem

项目选择器中的完整路径换行后，相邻选项被菜单布局压缩并叠字；大量相同前缀的目录也难以辨认。批量选择同时显示整理栏和删除栏、重复计数，压缩结果与详情。详情标题承载六个动作，消息收藏按钮仍显浏览器默认边框；片段收藏的筛选与刷新落在内容区，切换页签后操作位置跳变。搜索框可拖高、列表路径任意换行，也让同一视觉行高不稳定。

## Decision

项目菜单保持单行选项，名称优先显示目录末段，完整路径用悬浮提示获取；项目键仍由客户端与原始目录组成。选择模式仅保留一条上下文工具栏，计数、选本页、置顶、取消置顶、标签、删除和退出都由它拥有；标签编辑按需展开。会话与收藏共用页头筛选和刷新位置。详情标题突出恢复操作，导出、整理、置顶和删除进入更多菜单；整理使用已有标准弹窗，别名和标签编辑不再把正文推到首屏以下。恢复命令作为事实行保留复制入口。全部项目视图中，连续的相同项目结果只在组首显示一次可点击的目录；选定项目时不重复显示该目录。主页面固定在视口内，列表和正文各自滚动。列表、消息与空态统一截断、边框、触控目标和对齐。单条删除使用单条确认文案，收藏筛选同步约束右侧详情。此决定接续[项目筛选与结果布局](2026-09-24-session-layout.md)，保留项目筛选位于结果列表顶部的双栏结构。

## Alternatives considered

- 只给现有项目菜单加高度和换行规则，改动最小；但长路径仍会让每项高低不同，大量测试目录的共同前缀也遮住识别信息。
- 保留两条批量栏并缩小按钮，可减少局部拥挤；但重复计数、上下分散和选择态占用两行的问题仍在。
- 将详情所有动作继续常显并靠自动换行适配，发现成本低；但不同标题长度会改变操作位置，窄详情列无法形成稳定扫描锚点。
- 保留行内整理表单并只压缩字段间距，不需额外弹窗；但长原标题仍会推走阅读区，列表与正文不再共享稳定的可见高度。
- 每条结果都保留项目快捷按钮，可从任一项直达项目；但相同目录在连续结果之间反复占一行，目录选择器与详情也已提供项目入口。

## Consequences

- 项目选择器不再靠任意换行展示全路径，列表行高稳定；完整路径仍在提示中可查看。所有项目选择键和后端筛选契约保持原样。
- 批量栏只显示一次计数和一次删除入口；整理上限 200 条只约束整理动作，删除仍走原确认流程。退出选择模式会卸载标签草稿。
- 更多菜单增加一步点击，但有键盘可用的独立菜单项；单条删除和批量删除分别显示对应确认文案。收藏筛选后，右侧不再保留筛选外条目。
- 整理表单打开时由标准弹窗承载，长原标题在弹窗内截断并保留完整提示；导出多一步点击，换取标题可读宽度。项目组首仍可一键筛选，连续结果的目录不再重复。
- 依仓库验证约束，本次不运行编译、类型检查或自动化测试；代码静态检查与笔记结构校验可覆盖引用和文档一致性，运行时视觉效果仍需下一次获准构建后目视核对。
