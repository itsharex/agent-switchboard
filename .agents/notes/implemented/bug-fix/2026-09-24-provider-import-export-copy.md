# Agent Note: 导入与导出供应商页的反馈文案与行为对齐

Status: implemented

## Problem

「导入与导出供应商」四个页签的反馈文案在一轮审查中暴露出与行为不对齐的问题：

- CC Switch 导入成功的 toast 无条件输出「已导入 N 个供应商 · 0 个用量脚本」——导入成功即返回供应商页，toast 是唯一结果反馈，而无脚本导入占绝大多数，等于每次都报一个假零值；同页结果横幅按段条件隐藏零值，两处各自为政（横幅计「项」、toast 计「个供应商」）。
- 页签「本机数据库」不点明数据来自外部工具 cc-switch，易与本应用自建的状态数据库混淆；「测速候选」借用 cc-switch 的概念，本应用没有任何「测速」功能，连通性检测明确「仅确认可达」。
- 「导入 SQL」空态承诺「即可导入全部供应商」，但已存在行默认不选（覆盖是显式 opt-in），同设备重复导入同一文件时默认 0 选中、按钮禁用，承诺与行为相反。
- 零散不一致：读取/解析错误的详情行标签与状态胶囊撞词、导出跳过行的「未导出：」前缀与汇总行重复且与导入侧不对称、「刷新配置」可读成刷新客户端配置、全部所选撞重复时横幅以成功样式显示「已导入 0 项」。

## Decision

导入结果由 `src/app/cc-import-outcome.tsx` 持有：`ccOutcomeSummary` 拼接各计数分段并隐藏非必需的零值，`CcOutcomeText` 让结果横幅与 toast 使用同一文本并随界面语言更新。`ccOutcomeNeedsAttention` 是警告判定的唯一 owner：有未导入项或零导入时，横幅与 toast 均为 warning，页面留在结果页；确有导入、没有未导入项且列表刷新成功时才返回供应商页。旧 key `importDiscovery.result.summary` 和从 hook 引用页面组件的路径删除，无兼容读取。

面向用户的命名以本应用自有概念为锚：

- 页签「本机数据库」→「CC Switch 数据库」，空态提示同步点名；默认库的扫描按钮直接写 `cc-switch.db`。README 本就使用 "CC Switch"，界面不再回避工具名。
- 「测速候选」→「备选服务地址」，对齐契约层对 `custom_endpoints` 的定义（自动路由可用的额外请求目标）与全局「服务地址」术语；后端 `claude_endpoints.rs` 的错误文案同步。
- 「导入 SQL」空态改为「预览各供应商的完整配置并按需导入」，不承诺全部导入。
- 计数单位统一「项 / items」：`export.exported` 不再写「项供应商」。
- 本机配置详情行的错误标签统一为「错误详情」（`local.errorDetail`），不再与状态胶囊撞词；「刷新配置」→「重新扫描」，与扩展发现页的同一动作同名。

## Alternatives considered

- toast 保留独立模板 key（重写 `result.summary` 为条件段）：否——横幅与 toast 是同一结果的两个展示面，两份模板必然再次漂移；单一 owner 函数让两处不可能不一致。
- 页签名写「cc-switch 数据库」与文件名一致：否——产品文档与用户认知里的工具名是 "CC Switch"，`cc-switch.db` 只在指向具体文件时出现。
- 「测速候选」保留并补一句说明：否——应用内无测速功能可指，说明只会更长，术语本身错了就换术语。
- 零导入时直接返回供应商页、只用 toast 提示结果，可少留一步操作：否——用户带着导入预期操作，零导入应当警示；直接返回还会隐藏结果横幅。

## Consequences

- 收益：导入结果在横幅与 toast 两处持续一致，语言切换时已显示的 toast 也会更新；零导入时能看到警告横幅；页签一眼可辨数据来源；每个术语都能在应用内找到指代。
- 代价：`result.summary`、`local.readError`、`export.skipReason` 三个 key 及旧文案字符串全部删除，无过渡；中文老用户会看到页签更名。调用点残留已全文检索为零。
- `ccOutcomeSummary` 接受 `TFunction`，两处均由 `CcOutcomeText` 在渲染时取得当前语言；toast 持有该组件，结果文案无快照副本。
