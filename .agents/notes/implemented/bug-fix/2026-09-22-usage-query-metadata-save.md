# Agent Note: 用量查询保存保持供应商配置原样

Status: implemented

## Problem

在 Codex 供应商的用量查询页面只修改刷新间隔时，保存流程复用了编辑器草稿转换。该转换会对模型目录应用编辑器默认值，导致候选供应商的模型配置被误判为发生变化；如果该供应商当前生效，保存被分类为需要应用客户端配置，前端因此拒绝保存并显示“此修改只允许保存供应商资料，不能应用客户端配置”。

## Decision

用量查询保存通过 `codexUsageDraftFrom` 构造元数据专用草稿。该路径完整保留当前 Codex 供应商记录中的模型目录、路由、能力、连接和参数，只替换 `usageQuery`。编辑器草稿的默认值逻辑继续只服务于编辑器保存，不参与用量元数据保存；真正的客户端配置变化仍由后端的 `SaveAndApply` 分类和前端保护处理。

## Alternatives considered

### Why not remove the metadata保存的 `SaveAndApply` 拦截？

这会把真正伴随配置漂移的保存静默升级为客户端配置应用，破坏供应商资料保存与客户端切换的边界。

### Why not change the编辑器草稿默认值？

模型图片能力的默认勾选是现有产品决定；改变编辑器默认值会影响新建和编辑行为，不能解决元数据保存不应重写模型目录的问题。

## Consequences

用量查询只改刷新时间时不会再因为模型目录默认值变化而触发客户端配置应用，模型配置字段会保持原样。Codex 持久化字段新增时，元数据草稿构造路径必须同步保留该字段，否则后续用量保存可能丢失它。

## Verification

已检查用量保存调用改为 `codexUsageDraftFrom(record, usageQuery)`，该函数不再经过会应用编辑器默认值的 `codexDraftFrom`。针对本次改动运行 `git diff --check`，未发现空白错误；未运行项目编译或自动化测试，因为当前项目规则要求仅在用户明确要求时执行。
