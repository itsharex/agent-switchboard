# Agent Note: 供应商存储改为保留数据的智能修复

Status: implemented

## Problem

供应商存储读取失败时，界面目前只提供清空整个存储的入口。这会删除仍可读取的档案、客户端设置和切换记录，也无法指出具体失败文件。严格契约升级后，缺少新增加的自动设置键就可能触发此错误。

## Decision

存储修复仅处理能证明语义不变的差异：为当前契约缺失的设置意图补上 `automatic`，移除 JSON 文本开头的 BOM，保留其余字段、凭据和历史。先复制完整配置目录到独立暂存位置，在暂存副本上修复并通过现有严格读取器验证；确认原目录未被外部修改后交换目录，旧目录保留为可恢复副本。命令返回修复文件数和副本路径；无改动但已有效时返回成功。每个不能安全修复的文件给出相对路径与原因，保持原数据原样。

入口从“清空旧档案并重新开始”改为“一键智能修复”，删除清空命令、删除实现、旧日志动作和相关文案。启动直接初始化当前存储契约，删除永远返回未升级的迁移占位入口；旧布局标记由 `ConfigStore` 一处定义，读取与修复共用。修复只触及应用拥有的 `state/configuration/`；绝不写 Codex/Claude Code 的实际配置、凭据和网关路由。旧聚合格式或中断事务不能仅凭猜测转换，须明确报告，不隐藏标记或移走记录。

## Alternatives considered

- **继续保留清空入口作为失败后回退**：能让页面迅速恢复，但会丢失仍可用的供应商数据，与用户的明确要求冲突，放弃。
- **逐文件原地改写**：实现较少，但多文件修复失败时可能只完成一半，无法保证严格读取器接受整个存储，放弃。
- **自动丢弃未知字段或坏档案**：可以绕过严格校验，却无法证明业务含义不变，放弃。

## Consequences

当前设置键缺失时，一键补齐并保留其他记录；修复前原目录持久保留。前后端不再暴露清空供应商存储命令、日志兼容动作或文案，也没有第二套迁移入口。旧版清空日志行不再被当前日志读取器识别。修复不写真实客户端配置、账号绑定或用量历史，已有档案的含义不变。

完全无法解析的档案及无法推断语义的旧格式不能自动修复；应用给出可定位的错误，保持原数据不变。完整目录副本会增加一次磁盘占用，换来失败时可恢复。代码包含隔离临时目录的修复与拒绝案例；按照项目规则未运行编译和自动化测试。
