# Skill 与 MCP 管理当前状态

日期：2026-09-07。范围：扩展工作区当前实现；不读取、写入或迁移任何真实客户端配置。

后续完整实现顺序见 [执行方案](skill-mcp-management-execution-plan.md)。

## 当前结论

扩展库、计划、事务执行、恢复、来源解析、发现、部署、已有 MCP 编辑、Skill 自建与本地副本、批量目标与批量更新、按绑定固定版本、接管的用户流程和主要页面流程已经形成一条当前契约。仍不能把它称为设计全部交付：真实客户端隔离验证与跨平台故障验收未完成，发布时必须保持未验证能力阻断写入的状态。

已核对的当前边界：

- 定义、绑定、基线、计划、历史和内容版本由 asb-core extensions 契约拥有；持久化形状严格校验。
- `LocalState` 是扩展存储模式门禁的唯一所有者；`ExtensionStore` 只打开已经验证为当前版本的根目录，不会在运行中重复迁移或以 panic 掩盖失败。
- 一次性离线迁移先完整复制扩展根到暂存目录，再转换定义、绑定、基线、历史、项目、提交回执和 Skill 内容清单，并逐项按当前类型、目录摘要及实际内容树验证；未版本化检查记录原样保留。交换中断而根目录缺失时仅恢复唯一的精确目录备份；任何根目录、备份或文件类型歧义都会保留现场并阻断写入。
- asb-switch 是真实客户端配置的唯一写入层，计划先预览再确认；执行失败会回滚，并保留可恢复日志。
- 同一文档的基线会在同一事务中同步；未知原生字段在受管服务更新时保留；重复目标绑定被拒绝。
- Claude 项目私有 MCP 的服务项与 disabledMcpServers 成员在同一文档事务中更新，只撤销本应用证明拥有的成员。
- Skill 可显式扫描本地来源或解析 GitHub 固定提交，查看候选后才加入库。内容更新会生成部署预览，客户端写入仍需确认。
- 发现结果只向渲染器发送匿名观察 ID 和安全摘要。路径、项目根、原始文档、绑定 ID 与来源身份保留在后端；观察结果变更后导入会拒绝。
- 原生 MCP 导入在后端完整解析 Codex stdio/HTTP 与 Claude stdio/HTTP/SSE/WS。未知字段、字段冲突、未知传输和无法表达的值明确拒绝，绝不按 HTTP 猜测或通过表单丢字段。
- 已管理只在客户端、实际文档或目录与绑定完全一致时显示；同名项不会跨客户端或项目互相遮挡。Claude 项目私有 MCP 也会独立发现和导入。
- 已有 MCP 通过字段级编辑请求修改：保留 / 替换 / 删除逐字段表达，敏感值直接进入系统凭据存储，服务键重命名在同一计划中迁移全部绑定。
- Skill 支持自建模板、来源副本 fork 为本地副本、静态文件编辑与不可变内容版本；依赖指向库内 MCP 定义。
- 安装目标以多选表达，一次计划覆盖多个客户端与作用域；Skills 支持全库检查更新、逐项或全部更新；逐项报告新提交、文件级差异与失败原因，仅将存在启用绑定的更新合成统一部署预览。
- Skill 绑定可按绑定固定内容摘要：仅在目标与库当前版本一致时固定，固定后库与来源更新不再影响该目标，更新预览以警告目标说明跳过；解除固定恢复跟随。
- 本机项的「加入库」与「接管」分离：接管预览记录原始基线，移除绑定时恢复接管前内容；未知字段、同名冲突、外部改动等明确拒绝。
- 便携包导出只含不可变内容、定义与非敏感来源身份，凭据以占位符导出；导入后需重新提供凭据。

## 无兼容、无过渡的补齐原则

后续每项先为当前行为定义唯一的类型、后端命令和预览事务，再接页面入口、测试与文档。不要保留旧字段双读、表单预填回退、跨客户端路径回退或第二个真实配置写入器。需要改变持久化形状时，使用一次性离线转换并验证后只接受新形状；不要在运行时猜测或兼容两套结构。
